# Canonical research ZIP verification

Roadmap #54's remaining standalone research-archive gap is now aligned with the
existing stricter envelope checks of the seven other bundle families. This is
fail-closed consistency work, not a claim of a discovered exploitable vulnerability.
Those other seven implementations and the broader CLI input sweep are not changed.

## Compatibility change

The research bundle still has schema 2 and exactly seven fixed filenames. Its
builder algorithm is unchanged: STORED entries, fixed 1980 timestamp, Unix regular
file metadata, deterministic ordering and no comments/extras. A repack with exactly
the same bytes is valid. A recompression, alternate metadata/order, prefix, archive
comment or trailing bytes is now invalid even if payload hashes match. Previously
the standalone verifier accepted some such noncanonical envelopes; this intentional
acceptance change is not hidden as a format upgrade. Extra unbound manifest fields
also cannot survive the final whole-archive comparison.

The new helper belongs to ENGINE_FILES and research_bundle.py itself changes, so
real releases have different implementation fingerprints and therefore different
manifest/ZIP bytes. An old archive still needs its recorded trusted implementation.
No old archive or actual review is rewritten. Tests execute the actual previous
builder on four inputs and hold its recorded engine dictionary constant in the new
builder: the resulting entire ZIP bytes are identical. This controlled compatibility
check does not relabel an old archive as verified by a different implementation.

## Bounds and verification order

The existing inclusive maximum is **50,000,000 uncompressed entry bytes**, including
manifest, across all seven members. It is not redefined as a raw ZIP-file limit.
Canonical non-ZIP64 headers contribute exactly
`22 + sum(30 + 46 + 2 * len(UTF8(name)))`, currently 732 bytes. The raw read limit
is the uncompressed maximum plus that derived overhead. Thus a canonical archive
whose entry sum is exactly the limit passes both create and verify; one byte over
fails both. Protocol input to `create` is also read with a 50,000,000-byte bound,
which cannot exclude a previously accepted protocol because its bytes are already
part of the same total-entry budget. Exclusive output creation is unchanged.

`verify(path)` accepts an explicit filesystem path or seekable binary stream,
including BytesIO. It reads from offset zero with bounded, partial-read-aware reads,
then restores a caller-owned stream's original position without closing it.
`verify_bytes(bytes)` performs the same verification on exact bytes. Nonbinary or
nonseekable objects are not supported. A limit+1 byte is used only to detect excess.

Before any member payload is read, preflight checks the exact filename set, count,
no duplicates, declared uncompressed sum, no directory, no encryption flag,
STORED compression, equal compressed/uncompressed sizes, creator platform 3 and
regular-file type. Names are never extracted. CRC and normal ZIP structural checks
remain with Python's zipfile reader. Existing manifest, engine, payload hash and
regenerated-artifact checks run next, followed by exact comparison with the fully
rebuilt canonical ZIP. The latter rejects noncanonical timestamps, comments, extras,
ordering, EOCD differences, prefix/trailing data and otherwise unbound metadata.

Bounds cover raw input and declared member bytes, not an absolute limit on the ZIP
parser's total CPU or memory. This is not a secure-root or filesystem ancestor-race
API. There is no source authentication, signature, scientific assessment, search
completion or readiness promotion. CLI malformed-archive exceptions fail nonzero
without a traceback or a partial stdout success report.

## Rehearsal

From the repository root, use a new output pathname:

```sh
python research_bundle.py create examples/report-protocol.json canonical-research.zip
python research_bundle.py verify canonical-research.zip
```

Keep the generated bytes and recorded implementation. Do not rezip to repair a
failure or update old review hashes. A valid bundle verifies deterministic internal
consistency only. The synthetic regression matrix covers path and BytesIO/partial
reads, inclusive size symmetry, encrypted/compressed/type/name/duplicate/size
preflight rejection, CRC and EOCD errors, metadata and trailing bytes, exact repack
acceptance and unchanged canonical generation. Existing payload-tamper tests now
use the fixed canonical envelope so their original semantic errors are still tested,
not accidentally replaced by an earlier metadata rejection.
