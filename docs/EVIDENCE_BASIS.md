# Supplied result basis labels

This implements roadmap #41 with the reader adjustments: explicit declarations,
not source observations, scientific assessment, quality ranking or approval.
The `evidence` rows remain unchanged. Optional `evidence_bases` has one exact row
per existing `evidence_id`, with `text_access` (`ABSTRACT_ONLY`, `FULL_TEXT`,
`UNKNOWN`), `value_origin` (`REPORTED_NUMERIC`, `REPORTED_TEXT`,
`FIGURE_VISUAL_ESTIMATE`, `NOT_APPLICABLE`), and `finding_kind`
(`DIFFERENCE_REPORTED`, `NO_DIFFERENCE_REPORTED`, `MIXED`, `UNCLEAR`,
`OUTCOME_NOT_REPORTED`, `NOT_MEASURED_STATED`). None is inferred from result text.

Each row also requires `uncertainty`, `document_source_ids`, `declared_by`,
`declared_at` (real ISO date), and nonblank `limitations`. Uncertainty uses the
existing measurement state object: `reported` requires `value` and
`source_locator`; `not_reported`, `unknown`, or `not_applicable` requires `reason`
and `source_locator`. Values remain text, never numbers interpreted by this tool.

Selected document IDs must belong to the report containing that result's record.
An empty list is permitted without reports. Multiple documents are allowed; the
template only displays their catalog and leaves the selection null. A null source
hash is shown as `DOCUMENT_BYTES_UNBOUND`; a supplied hash is still unverified.
No document is opened. Result-intake source references and source-file observations
are never copied into this persistent declaration ledger automatically.

Figure-estimate declarations combined with reported treatment/comparator values
or dispersion, or contrast estimate/uncertainty, produce only a coexistence cue.
They are not rejected as inconsistent and are not promoted to exact values.
For a figure estimate without an exact reported value, use the existing statistics
`not_reported` state and put the explanation in `reason`. No-difference wording
is not evidence of absence of an effect. Unreported/unmeasured outcome rows still
count in `flow.extracted`.

## Explicit binding and compatibility

Without `evidence_bases`, prior run output and statement/work bases are unchanged.
Presence is an explicit stage transition, including `[]`: statement/work bases
then include the selected validated declarations and selected document descriptors.
Adding or editing related labels/descriptors can therefore make existing source-bound
reviews/challenges/work assertions stale under the existing rules. This is intentional;
no old review is renewed and no gate policy or scientific acceptance rule is added.
Once the stage exists, unrelated label rows do not enter a statement/work basis.
The displayed document catalog is not evidence that all those documents were read.

The intake is append-only, with 1–100 candidates per batch, 10 MB candidate input,
50 MB protocol/application limits and a 50 MB whole label-ledger limit. There is
no engine row-count cap of 100. Existing label correction is outside this command.
Template human fields are null. A separate exact-input review authorizes recording,
not endorsement. Replay compares the entire detached record; consistently reauthored
unsigned assertions can still replay, so identity, history and chronology are not
verified. Review records are not injected into the protocol ledger.

ENGINE changes are explicit: evidence_workflow, synthesis_links, planning_links,
adapter_integrity, bibliographic_integrity, research_bundle, plus the new
evidence_basis_links module. Bibliographic `ENRICHMENT_FIELDS` adds only
`evidence_bases`; adapter allowances add the same field. Old application/bundle
replay needs its recorded trusted implementation. Only the fixed 15 synthetic
example target-hash fields are maintained, never actual user or human-review data.
No automatic review-refresh tool is introduced.

Default views preserve prior data apart from named implementation fingerprints
and one new static handoff catalog route. Optional label queues/fields are absent
when the ledger is absent, rather than adding null fields to legacy output.
The preserved round43 baseline test spells out each named hash path and that one
route; it does not discard arbitrary output fields. The existing schema2 snapshot
contract is retained with opt-in additions only.

## Synthetic end-to-end rehearsal

Run in a fresh working directory with the repository's `examples` available.
All examples are fictional. No real review is generated by these commands.

```sh
python evidence_basis_intake.py template examples/synthesis-review.json examples/evidence-basis-references.json --candidate-output basis-blank.json
python evidence_basis_intake.py target examples/synthesis-review.json examples/manual-evidence-basis-candidates.json --output basis-target.json
```

Inspect `basis-target.json`, including the before/after readiness and stale review
context. A separate person supplies all blank `review_document` fields, sets
`decision` to `import_evidence_bases`, and saves only that document as
`basis-review.json`. Do not copy a stale target or invent a person's review.
The test rehearsal fills these fields with explicitly fictional test assertions.

```sh
python evidence_basis_intake.py assemble examples/synthesis-review.json examples/manual-evidence-basis-candidates.json basis-review.json --output basis-application.json
python evidence_basis_intake.py verify examples/synthesis-review.json basis-application.json --protocol-output basis-protocol.json
python evidence_basis_review.py basis-protocol.json --text
python research_status.py basis-protocol.json --text
python synthesis_review.py basis-protocol.json --text
python compare_runs.py examples/synthesis-review.json basis-protocol.json --text
python review_handoff.py basis-protocol.json --text
python research_bundle.py create basis-protocol.json basis-bundle.zip
python research_bundle.py verify basis-bundle.zip
```

New output files are exclusive. This rejects an existing final entry, including a
dangling symlink, but is not a secure-root/ancestor-race defense. A write failure
can leave a partial new output; do not treat its existence as successful completion.
The new CLIs emit a fixed error on stderr with empty stdout for invalid inputs or
output failure; no supplied text or path is embedded. They make no network call.
