# Reviewed screening-sheet positions intake

This separate wrapper closes the edited-sheet positions gap without changing
canonical screening. It appends supplied assertions to `screening_reviews` only.
Reviewer supersession is **not implemented**: duplicate review IDs and second
(record_id, reviewer) pairs fail through the existing engine validator.

## Four steps

1. Export with [screening_sheet.py](SCREENING_SHEETS.md). Retain the exact original
   protocol and sheet outside this repository. A sheet may select a subset of
   exported rows, but no row may be duplicated and no read-only cell may change.
2. A human fills every human column for each intended position. Fully empty human
   rows are skipped and listed explicitly; a partially filled row rejects the
   whole sheet. Run `target` and inspect the proposed append and before/after cues.
3. A separate human import review supplies receipt_id, reviewer, reviewed_at and
   rationale for the exact target. The decision is `import_screening_reviews`.
   It authorizes recording only, not endorsement or adjudication. Run `assemble`.
4. Run `verify` against the unchanged original protocol and application, then
   optionally write a new protocol. No original file is overwritten.

Dates must stay `YYYY-MM-DD`, not spreadsheet locale dates. Save as UTF-8 CSV.
The parser preserves CR/LF, BOM and quoted multiline byte provenance. Human cells
are literal: values starting with an apostrophe, formula prefix (`=`, `+`, `-`,
`@`) or whitespace are rejected, never silently unescaped. If a literal value
requires such a prefix, this bounded CSV wrapper cannot import it; use the
existing [JSON workflow](SCREENING_REVIEWS.md), preserving the actual assertion.
Read-only IDs may have those prefixes: their escaped display is compared exactly,
and the literal JSON ID plus source hash disambiguate apparent collisions.

Any protocol change, even outside the source basis, invalidates the export
protocol hash. Never refill an old hash or rebase the sheet automatically. Export
fresh context and have the human re-examine it. Every read-only display and locator
cell is regenerated for exact comparison. Retained values and locators are inert,
not parsed for meaning, fetched or executed. Existing assertions remain unchanged.

## Synthetic walkthrough

Run from the repository root, replacing `OUTPUT` with an existing empty directory
outside the checkout. The checked-in CSV and import review are entirely synthetic.
They demonstrate already supplied human assertions, not decisions generated by
this tool. Inspect the target and compare it to the fixture review before assembly.
For real work stop after target and have a human fill the review document instead.

```sh
python screening_sheet_intake.py target examples/screening-reviews.json examples/screening-sheet-intake/filled.csv --output OUTPUT/target.json
python screening_sheet_intake.py assemble examples/screening-reviews.json examples/screening-sheet-intake/filled.csv examples/screening-sheet-intake/import-review.json --output OUTPUT/application.json
python screening_sheet_intake.py verify examples/screening-reviews.json OUTPUT/application.json --protocol-output OUTPUT/protocol.json --output OUTPUT/verification.json
```

The application embeds exact CSV bytes (base64), SHA-256, parsed literal human
cells and source spans, the original protocol hash, implementation hashes, review,
and candidate. Verification replays all of them. Retain the detached application:
the new protocol contains only positions, not this import receipt. Hashes detect
drift, not authentication; consistently reauthored unsigned records can replay.
Reviewer identity, reading, source authenticity and scientific validity remain
unestablished. No vote, consensus, adjudication or conclusion readiness is inferred.

Limits: 10 MB CSV, at most 10,000 sheet rows and 100 completed positions per import,
50 MB protocol/application; existing engine constraints also apply. Outputs use
exclusive creation, including final symlink refusal. Missing parents fail. Writes
are not atomic; errors can leave partial new files. With two output paths, a later
failure may leave the first successfully written file. No ancestor-alias/race
security guarantee is made. Real sheets can contain unredacted abstracts: never
commit them or their detached applications to this public repository.
